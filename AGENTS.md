# Правила для ИИ-агентов — Things 2

Приложение для задач на Android (Kotlin, Jetpack Compose, Hilt, Room). У него есть десктопная версия в соседнем
репозитории `Things Desktop`, которая при сборке берёт исходники отсюда. Общайся с пользователем и пиши
комментарии в коде по-русски.

## 1. Как работать

- **Делай то, что просили.** Попутно замеченные ошибки, лишний код и «можно лучше» не исправляй молча — сообщи о
  них в ответе. Если просили рефакторинг или исправление замечаний — делай в нужном объёме, не ограничиваясь
  одним файлом.
- **План — перед крупной задачей** (новая функция, переделка экрана, перенос кода между модулями): коротко опиши
  шаги и дождись согласия. Для мелкой правки план и вопросы не нужны.
- **Уточняй только то, что нельзя выяснить из кода** и от чего зависит результат. Не спрашивай о том, что можно
  проверить самому.
- **Перед правкой перечитай файл**: в этом дереве работают и другие агенты, и сам пользователь. Перед сборкой
  посмотри `git status` и недавно изменённые файлы; о чужих правках, влияющих на результат, скажи — не откатывай
  их сам.
- **Отчёт — по факту.** Что сделано и проверено, что не проверено, что упало. Не называй исправленным то, что не
  проверял.

## 2. Коммиты и отправка

- Коммит — только по слову «коммит», отправка на GitHub — только по слову «пуш».
- Отдельный коммит на каждое смысловое изменение. Сообщение на русском, подробное: что изменено, зачем и чем
  проверено. Заголовок с приставкой `fix:`, `feat:`, `refactor:`, `build:`, `ci:`, `docs:`, `perf:`, `tools:`.
- `git add` — только явными путями. Не добавляй чужие и неотслеживаемые файлы, которые не создавал сам.
- Ветка `main`; проверка на GitHub (`.github/workflows/ci.yml`) запускает тесты и Lint на каждую отправку.

## 3. Проверка перед коммитом

```bash
./gradlew :shared:test :app:testDebugUnitTest
```

```bash
./gradlew :app:lintDebug
```

- Запускай полные тесты перед каждым коммитом, даже после «чисто визуальной» правки.
- Lint: прежние замечания записаны в `app/lint-baseline.xml`, новое замечание — ошибка. Исправляй причину, а не
  добавляй запись в список.
- Изменил стиль темы (`ui/theme`) — пересоздай документацию и включи её в тот же коммит:
  `./gradlew :app:testDebugUnitTest --tests "*DesignSystemDocSyncTest" -DgenerateDesignDocs=true`
- Изменил файл, общий с десктопом (см. раздел 6), — собери и протестируй десктоп тоже.

## 4. Проверка на телефоне

Исправление поведения или внешнего вида считается готовым только после проверки на реальном телефоне. Если
телефон недоступен — скажи прямо, что не проверено.

- Ставь релизную сборку: `./gradlew :app:installRelease` (подписана отладочным ключом, данные сохраняются).
  Отладочная сборка заметно тормозит на переходах — о плавности по ней судить нельзя.
- Для жестов и тестовых данных есть отдельное приложение «Things QA» со своей базой: `./gradlew :app:installQa`.
- В рабочем приложении лежат настоящие данные пользователя. Создавай и удаляй только объекты с приставкой `ZZ`.
  Чужие задачи не редактируй, не перемещай и не завершай.
- Не трогай телефон, пока им пользуется владелец: проверь, что на экране `com.bgdlab.things`, иначе подожди.
- Перед каждым жестом убедись, что клавиатура закрыта: жест поверх клавиатуры печатает в открытое поле. Если
  касание открыло клавиатуру — сначала закрой её.
- Свайп вниз у верха списка открывает поиск. Первое касание после запуска часто не срабатывает.

## 5. Архитектура

```
app/                  Android-приложение
  ui/                 экраны и компоненты Compose, тема, ThingsViewModel
  data/               репозиторий, источники данных, Room, синхронизация
  di/                 модули Hilt
shared/               правила и модель данных — общие с десктопом (отдельная сборка Gradle)
  domain/             сценарии (UseCase), правила списков, повторов, правок
  data/model/         модель данных
baselineprofile/      съёмка профиля запуска (нужна только для :app:generateBaselineProfile)
tools/                desktop_sync.py — согласование с десктопом
docs/                 дизайн-система, иконка, список дел перед выпуском
```

- Зависимости идут в одну сторону: UI → ViewModel → Domain ← Data.
- Экран только показывает состояние и передаёт события. Бизнес-правила — в `shared/domain`.
- `ThingsViewModel` обращается к данным только через группы сценариев (`TaskUseCases`, `ProjectUseCases`,
  `AreaUseCases`, `TagUseCases`, `ChecklistUseCases`, `HeadingUseCases`, `QueryUseCases`, `SyncUseCases`),
  никогда — напрямую к `ITaskRepository` или источникам данных.
- В `shared/` нет Android: только Kotlin/JVM. Аннотации Room там — `compileOnly`.
- Свойства модели из `shared/` не приводятся автоматически после проверки на null — бери значение в локальную
  переменную. `internal` из `shared/` приложению не виден.
- Не раздувай большие файлы. Новую самостоятельную часть экрана выноси в отдельный файл рядом
  (`ui/screens/home/components`, `subcomponents`).
- Изменение схемы базы — это новая версия Room, миграция и файл схемы в `app/schemas`; десктопу нужна та же
  схема (см. раздел 6).

## 6. Десктоп

Десктоп (`../Things Desktop`, отдельный репозиторий) не хранит копий общих файлов: при сборке он берёт
`app/src/{main,test}/java/com/example/**/*.kt` отсюда. Исключения перечислены в `tools/desktop_sync.json`:
`phone_only` (только Android) и `desktop_owned` (своя версия десктопа), плюс файлы, для которых у десктопа есть
своя копия с добавками под мышь и окно.

- Правка общего файла меняет и десктоп. После неё: сборка и `desktopTest` в репозитории десктопа.
- Новый файл десктоп подхватит сам. Если он только для Android и ломает сборку десктопа — добавь его в
  `phone_only`.
- Копии десктопа, которые отличаются от телефона: `python -X utf8 tools/desktop_sync.py status|diff|pull`.
  Конфликт слей вручную, затем `baseline ФАЙЛ`. Копия стала одинаковой с телефоном — `share ФАЙЛ`.
- Строки: после правки `res/values*/strings.xml` выполни `python -X utf8 tools/desktop_sync.py strings`.
- Телефон и десктоп синхронизируются через один файл на Google Drive. `shared/domain` и кодек синхронизации
  должны оставаться совместимыми: файл новой схемы старая версия приложения не читает.

## 7. Оформление интерфейса

- Никаких значений «на месте»:
  - цвета — `ThingsTheme.colors` (не `MaterialTheme.colorScheme`);
  - шрифты — `ThingsTheme.type`;
  - формы — `ThingsTheme.shapes`;
  - размеры и отступы — `MaterialTheme.dimens`;
  - длительности анимаций — `ThingsMotion`;
  - тексты — `strings.xml` на трёх языках (украинский, русский, английский) через `stringResource()`.
- Образец поведения и вида — приложение Things 3. Если пользователь дал эталон (скриншот, видео) — сверяйся с
  ним, а не с собственным вкусом.
- Числовое состояние — `mutableIntStateOf` / `mutableFloatStateOf`. Состояние, которое меняется на каждый кадр
  (прокрутка, перетаскивание), читай в `graphicsLayer`/`layout` или через `derivedStateOf`, а не в теле функции.
- Комментарий пиши там, где неочевидна причина: почему именно так, какое ограничение обходится. Очевидное не
  комментируй.

## 8. Безопасность и данные

- Не выводи и не коммить токены, ключи и пароли. `local.properties`, `.env`, хранилища ключей — вне репозитория.
- Перед прямой правкой базы данных сделай её копию.
- Необратимые действия (удаление данных пользователя, `git push --force`, сброс истории) — только с явного
  согласия.
- До самого выпуска не делай: собственный ключ подписи, схему версий, переименование пакета. Полный список —
  `docs/release-checklist.md`.

## 9. Сборка

- Версии библиотек — в `gradle/libs.versions.toml`. Свежие версии AndroidX требуют Android Gradle Plugin 9.1+;
  переход на него — отдельная задача, не побочная правка.
- `gradle.properties` задаёт JDK локальной машины (`org.gradle.java.home`); на GitHub его перекрывает сама
  проверка.
- Тесты `shared/` запускай из корня (`./gradlew :shared:test`), а не из папки модуля.
- Профиль запуска переснимается командой `./gradlew :app:generateBaselineProfile` с подключённым телефоном;
  особенности описаны в `baselineprofile/build.gradle.kts`.
